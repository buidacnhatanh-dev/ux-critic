## M1 · Demo data (2026-10-17)

Built

* `eval/fixtures/`: five fixture pages (Checkout practice v1, v2, v3, Sign up form, Analytics dashboard), each with `*.expected.json` listing the planted problems with `principle_id` and a CSS selector. Shared `base.css` loads fonts from `node_modules/@fontsource` only; the capture blocks every non file request
* `pnpm demo:capture` (`scripts/demo-capture.ts`): Playwright at 1280 × 800, scale 2, to `public/demo/*.png`, plus `demo/captures/*.json` with the text line, control and planted element boxes
* `lib/contrast.ts`: WCAG luminance and ratio (known pairs from docs/04 tested), thresholds, OKLCH and the nearest passing colour
* `lib/pipeline/measure.ts`, `measure-screen.ts`, `measured-text.ts`, `order.ts`, `image.ts`: background ring, text colour, contrast, text size, tight target box, target size, the docs/04 issue wording, and reading order numbers. Unit tested on synthetic images, including anti aliased text rendered with sharp
* `pnpm demo:data` (`scripts/demo-data.ts`): runs the measuring code on the PNGs and writes `demo/data.json` with `source: "handwritten"`. Measured issues and all measurements are computed. Evaluated issues come from `demo/handwritten.json`, written from the planted problems, with principle and region taken from the fixture. The script stops if a planted measured problem is not found, or if something unplanned fails
* `lib/data/demo-schema.ts` (zod) validates the data when it is written and in a unit test
* `DemoClient`: every `DataClient` method on top of `demo/data.json` (loaded once, as its own chunk) and the visitor's overlay in `localStorage` (`uxc-demo-v1`): pushbacks (including undoing the prepared one), deleting projects, checklist changes, and new reviews from a sample screen with simulated steps (about 6 s, `instant` for reduced motion; measured results appear before evaluated ones). Every storage call is wrapped; blocked storage keeps changes in memory. `resetDemo()` clears it all. `listSamples()` added for the New review picker

Result: 3 projects, 5 reviews, 17 issues (5 measured, 12 evaluated), 344 measurements. Checkout v3 has no issues. The faint helper text measures 1.85 : 1, the reference value from docs/04

Decisions

* **Where things are vs what they measure.** In the demo scripts the text lines and controls are located from the page at capture time, standing in for OCR and Claude call 1. Every value (contrast, text colour, target size) is computed from the PNG pixels by the same code live mode will use. Text size is estimated from the located line height, as docs/04 says
* **Fixture font.** The docs/04 estimate (line height ÷ scale ÷ 1.2) is accurate for Atkinson Hyperlegible and Overpass (within about 2 px) but underestimates Arial and Helvetica by 1 to 2 px, which would flag 16 px text. Fixtures use Atkinson and Overpass. Live mode (M5) will need a check of this formula against real OCR boxes
* **Contrast severity** is high below 3 : 1 and medium otherwise (docs/04 does not say). Target size: one issue per control, WCAG 2.5.8 (medium) first, the 44 px rule (low) only when WCAG passes. Both checks are kept as measurements
* **Handwritten reviews** have `model`, `inputTokens` and `outputTokens` set to null (types now allow null), and `finishedAt` equal to `startedAt`, so no duration or token number is ever shown for them
* Seed rules use stable UUIDs (v5 from their key); fixtures refer to them as `rule:<key>`
* `.gitignore` had `data/`, which also matched `lib/data/`, so the M0 commit was missing `lib/data/`. Now `/data/` and `/eval/runs/` are anchored to the root, and `lib/data/` is committed
* Playwright starts its dev server with its own build folder (`UXC_DIST_DIR=.next-e2e`), so `pnpm test:e2e` works while `pnpm dev` is running
* ESLint also blocks relative imports of `lib/pipeline` and `lib/db` from screens and the data clients
* Node 24 runs the scripts directly (built in type stripping), so no new dev dependency; script reachable `lib/` files use `.ts` import extensions (`allowImportingTsExtensions`)
* New dependencies from the CLAUDE.md stack: `sharp` (its install script is allowed in `pnpm-workspace.yaml`) and `zod`

A refusal or a cut off answer that still comes back makes the review partial
* The measure step is still empty in M5: OCR, call 1 and the measuring maths are M6. Its place in the pipeline already saves before evaluation starts, so the Reviewing screen shows "0 problems found by measuring" for now
* `DataClient` gained optional `restartReview` (Try again) and `getUsage` (spend line), live only
* Prepare stores the upload as PNG in the API route (to know width and height for the version), and the pipeline's prepare step makes the image for Claude from that file. An upload sharp cannot read is refused on the form ("This file couldn't be read…")
* `fake-slow` (8 s) was added to the fake AI fixtures so Playwright can press Cancel review while a review runs; docs/03 updated
* The principle set checkboxes on My checklist now change at once while the change is saved (the live round trip made them lag), and New review leaves out a project deleted while the form loads instead of failing
* The shell test that measures the narrow layout waits for the page heading first; with three dev servers running it sometimes measured too early
* New dependencies, all in the CLAUDE.md stack: `drizzle-orm`, `better-sqlite3`, `@anthropic-ai/sdk`; dev: `drizzle-kit`, `@types/better-sqlite3`. `pnpm-workspace.yaml` allows the `better-sqlite3` build script

## M6 · Live mode: measured checks (2026-10-18)

Built

* `lib/pipeline/ocr.ts`: tesseract.js (English and German, LSTM) on the original screenshot. Four passes merged (sparse text and automatic layout, each with the global and a local threshold), noise words such as input borders dropped, lines split at wide gaps, then the docs/04 filter (confidence ≥ 60, ≥ 2 characters). One worker per server process, one OCR at a time. On the five demo screens it finds 128 of 129 text lines, including the faint `#B9BFC8` helper text, in about 2 to 3 s each
* Text size from OCR lines: `min(row height, 1.25 × glyph box) ÷ scale ÷ 0.87` (`estimateFontSizeFromOcr`). The docs/04 formula (line box ÷ 1.2) assumes Chromium line boxes; OCR boxes are tight around the glyphs and would read 16 px text as about 10 px. Checked against the CSS sizes of the demo screens, findings in docs/04. The demo path still uses the line box formula; `pnpm demo:data` writes the same `demo/data.json` byte for byte
* `lib/pipeline/locate.ts`: Claude call 1 with the docs/03 prompt and schema, `output_config.format`, then zod: integers ≥ 0, width and height ≥ 4, boxes inside the image; invalid items are dropped, an unreadable answer skips target sizes. Boxes are mapped back to original pixels (× f), then the M1 code measures the tight box
* The measure step in `lib/pipeline/run.ts` reuses the M1 measuring code (`measureScreen`): contrast and text size for every OCR line, target size for every located control, every check saved to `measurements` (pass or fail) and failures saved as measured issues, numbered in reading order, all before evaluation starts. Call 1's tokens are saved with them; call 2 adds its own
* Measured rules from My checklist apply when they were on for the review and "My checklist" is a source; with two rules for one metric the stricter one counts
* Failing measurements go into the evaluation prompt with units: `contrast, "Terms", 2.1 : 1, needs 4.5 : 1`
* Measured checks only (no key): OCR, contrast and text size run; call 1 and call 2 are skipped. The Review screen keeps "Evaluation is off…" and adds "Target sizes weren't measured: Claude finds the controls before code measures them. Contrast and text size were measured from pixels." The same kind of note appears when call 1 fails or is unreadable (with technical details), and when OCR fails (the review then goes on to evaluation). Shown on Review, Evaluation unreadable and No issues found
* Evaluation unreadable (11) and Retry evaluation now show real measured issues; Retry evaluation does not measure again
* Fake AI mode: call 1 answers from its fixtures (`fake-unreadable` and `fake-timeout` skip target sizes). `fake-slow` is slow only for call 2
* Tests: OCR cleaning, splitting and merging, plus one real OCR run on the checkout v1 screenshot; call 1 parsing; the OCR size estimate; measure step runs (saved before call 2, passed into the prompt, measured only, call 1 failed or unreadable, boxes mapped from a downscaled image, OCR failure, retry does not measure again, token sums); measured rules; skipped check notes. Zero axe violations

Decisions

* **Language data from npm, not a CDN** (asked and agreed): tesseract.js downloads its data from jsdelivr by default, which breaks "no third party requests". New dependencies `@tesseract.js-data/eng` and `@tesseract.js-data/deu` (plus `tesseract.js` from the stack). tesseract.js reads all languages from one folder, so the data is copied once to `data/tessdata`. Passing the data in memory does not work in tesseract.js 7 (it initialises with the data instead of the language code). Its install script only prints an Open Collective message and is not allowed to run (`pnpm-workspace.yaml`)
* `tesseract.js` is a server external package in `next.config.ts` (it starts a worker thread from a file in the package), and the data path is resolved from the project folder at runtime, because Turbopack rewrote `require.resolve` to a path that does not exist
* `reviews.skipped_checks` (new column, migration `0001_measured_checks`): which measured checks did not run and why (`no_claude` or `failed`, with detail). docs/02 updated
* A failed OCR does not fail the review: text checks are skipped with a note and the evaluation still runs, like a failed call 1 (docs/03 only covers call 1)
* Text size factor 0.87, not the measured average 0.92: it leans toward reading high, so 16 px body text is not reported as 15 px. Reading high can miss text that is 1 px too small; reading low reports a problem that is not there
* The "measurements table" in the milestone is the `measurements` database table (every check, pass or fail, used by Compare); the designs have no table on screen, so none was added
* Live Playwright tests upload checkout v1 (faint text) or v3 (measures clean, for No issues found), and wait up to 45 s for a result because OCR runs one screenshot at a time while tests run in parallel
* With real call 1 boxes and code based sizes, the fake call 1 fixture's two controls land on empty areas of the demo screenshots and measure nothing; target size results are covered by unit tests with synthetic images
