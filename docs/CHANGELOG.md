# Changelog

## M0 · Scaffold, tokens, components, modes (2026-10-17)

Built

* Next.js 16 App Router, TypeScript strict (plus `noUncheckedIndexedAccess`), pnpm, ESLint (next core web vitals + typescript, Prettier compatible, zero warnings allowed), Prettier, Vitest with Testing Library, Playwright with `@axe-core/playwright`, Fontsource fonts (no Google requests), `.env.example`
* `app/tokens.css` with every token from docs/01, plus spacing, type sizes and a few colours the designs use (`--color-bg`, `--color-on-dark`, `--color-primary-dashed`, backdrop and shadows) so components never use raw hex
* `components/ui/`: Button (+ ButtonLink), TextField, Textarea, Select, Checkbox (+ CheckboxGroup), RadioGroup, Dialog, Toast, Announcer, Tooltip, Pill (+ SeverityPill, SeverityCountPill, KindPill), each with a unit test
* `/dev/ui` preview (404 outside development) with every variant and state
* `DataClient` interface and types (`lib/data/`), `DemoClient` and `LiveClient` that reject with `NotImplementedError` (M1 / M5), `useDataClient()`, and the mode switch `lib/mode.ts` read by the root layout
* Sidebar shell from design 01 with the Demo pill, source line, "How this demo works" dialog and "Reset demo" (works now: clears `uxc-demo-v1`), skip link, and empty pages for every route including `/states`
* `proxy.ts` returns 404 for every `/api` path in demo mode
* Playwright: every route renders the shell with zero axe violations, keyboard flows for both demo dialogs, focus ring on every focusable element of `/dev/ui`, narrow window stacking, API 404 in demo

Decisions

* TypeScript is pinned to 6.x: typescript-eslint does not support TypeScript 7 yet
* Extra dev dependencies needed by the listed tools: `@vitejs/plugin-react`, `jsdom`, `@testing-library/dom`, `@testing-library/user-event`, `@testing-library/jest-dom`, `eslint-config-next`, `eslint-config-prettier`
* `UXC_MODE=live` with `UXC_FAKE_AI=1` counts as live without a key, so live flows can be tested later without network. Anything other than exactly `live` is demo
* In demo mode the sidebar shows the demo block instead of "Private · runs on this laptop" (the demo is not on a laptop)
* Navigation uses `aria-current="page"` on the exact page and `aria-current="true"` for the section (Projects stays highlighted on Project history, Review and Compare, as in the designs)
* `demo/data.json` exists with empty `projects` and `reviews`; until M1 fills it the source line reads "Sample reviews written by hand". It only switches to "Reviews generated by Claude on <date>" when every review has `source: "claude"`
* Reset demo asks in an alert dialog with "Keep my changes" focused first, then shows a toast
* Toasts announce through the shared Announcer; the toast region itself is not a live region
* ESLint blocks imports of `@/lib/db` and `@/lib/pipeline` outside API routes, the pipeline, the database and the live client
* The mode is read when a page renders; static pages bake it in at build time, which is fine because the mode is a deployment setting

## M1 · Demo data (2026-10-17)

Built

* `eval/fixtures/`: five fixture pages (Checkout practice v1, v2, v3, Sign up form, Analytics dashboard), each with `*.expected.json` listing the planted problems with `principle_id` and a CSS selector. Shared `base.css` loads fonts from `node_modules/@fontsource` only; the capture blocks every non file request
* `pnpm demo:capture` (`scripts/demo-capture.ts`): Playwright at 1280 × 800, scale 2, to `public/demo/*.png`, plus `demo/captures/*.json` with the text line, control and planted element boxes
* `lib/contrast.ts`: WCAG luminance and ratio (known pairs from docs/04 tested), thresholds, OKLCH and the nearest passing colour
* `lib/pipeline/measure.ts`, `measure-screen.ts`, `measured-text.ts`, `order.ts`, `image.ts`: background ring, text colour, contrast, text size, tight target box, target size, the docs/04 issue wording, and reading order numbers. Unit tested on synthetic images, including anti aliased text rendered with sharp
* `pnpm demo:data` (`scripts/demo-data.ts`): runs the measuring code on the PNGs and writes `demo/data.json` with `source: "handwritten"`. Measured issues and all measurements are computed. Evaluated issues come from `demo/handwritten.json`, written from the planted problems, with principle and region taken from the fixture. The script stops if a planted measured problem is not found, or if something unplanned fails
* `lib/data/demo-schema.ts` (zod) validates the data when it is written and in a unit test
* `DemoClient`: every `DataClient` method on top of `demo/data.json` (loaded once, as its own chunk) and the visitor's overlay in `localStorage` (`uxc-demo-v1`): pushbacks (including undoing the prepared one), deleting projects, checklist changes, and new reviews from a sample screen with simulated steps (about 6 s, `instant` for reduced motion; measured results appear before evaluated ones). Every storage call is wrapped; blocked storage keeps changes in memory. `resetDemo()` clears it all. `listSamples()` added for the New review picker

Result: 3 projects, 5 reviews, 17 issues (5 measured, 12 evaluated), 344 measurements. Checkout v3 has no issues. The faint helper text measures 1.85 : 1, the reference value from docs/04

Decisions

* **Where things are vs what they measure.** In the demo scripts the text lines and controls are located from the page at capture time, standing in for OCR and Claude call 1. Every value (contrast, text colour, target size) is computed from the PNG pixels by the same code live mode will use. Text size is estimated from the located line height, as docs/04 says
* **Fixture font.** The docs/04 estimate (line height ÷ scale ÷ 1.2) is accurate for Atkinson Hyperlegible and Overpass (within about 2 px) but underestimates Arial and Helvetica by 1 to 2 px, which would flag 16 px text. Fixtures use Atkinson and Overpass. Live mode (M5) will need a check of this formula against real OCR boxes
* **Contrast severity** is high below 3 : 1 and medium otherwise (docs/04 does not say). Target size: one issue per control, WCAG 2.5.8 (medium) first, the 44 px rule (low) only when WCAG passes. Both checks are kept as measurements
* **Handwritten reviews** have `model`, `inputTokens` and `outputTokens` set to null (types now allow null), and `finishedAt` equal to `startedAt`, so no duration or token number is ever shown for them
* Seed rules use stable UUIDs (v5 from their key); fixtures refer to them as `rule:<key>`
* `.gitignore` had `data/`, which also matched `lib/data/`, so the M0 commit was missing `lib/data/`. Now `/data/` and `/eval/runs/` are anchored to the root, and `lib/data/` is committed
* Playwright starts its dev server with its own build folder (`UXC_DIST_DIR=.next-e2e`), so `pnpm test:e2e` works while `pnpm dev` is running
* ESLint also blocks relative imports of `lib/pipeline` and `lib/db` from screens and the data clients
* Node 24 runs the scripts directly (built in type stripping), so no new dev dependency; script reachable `lib/` files use `.ts` import extensions (`allowImportingTsExtensions`)
* New dependencies from the CLAUDE.md stack: `sharp` (its install script is allowed in `pnpm-workspace.yaml`) and `zod`

## M1 follow up · Sample products restyled (2026-10-17)

* The five fixtures now look like three fictional products, clearly not UX Critic: **Little Fern Coffee** checkout v1 to v3 (cream page, white checkout sheet, dark green `#1F4A36`, Cormorant Garamond headings, Figtree text), **Rally** fitness sign up (white with an orange `#C2410C` panel and buttons, Rubik), **Waypoint Freight** logistics dashboard (dark `#0F1720`, teal `#2DD4BF`, Barlow Semi Condensed). No fixture uses `#1D4ED8`, Atkinson Hyperlegible or Overpass
* `base.css` is now only a reset; each product has its own stylesheet (`coffee.css`, `fitness.css`, `logistics.css`). `checkout.css` is gone
* Every planted problem is the same element, principle and kind of failure. The faint helper text is still `#B9BFC8` on white (1.85 : 1). `demo:data` found every planted measured problem and nothing else
* Measured values that changed (computed): the dashboard footnote is now 2.81 : 1 on the dark card (was 3.10 : 1 on white); 352 measurements (was 344)
* Fonts were chosen by testing the docs/04 estimate at 12 to 40 px (within 1 px), then checked again on the captured pages (worst 0.8 px). Fredoka passed the first test (+0.67 px) but reached 1.08 px on the page once boxes snap to whole pixels, so the sign up form uses Rubik instead. Note added to docs/04
* Handwritten prose and contexts updated for the new products (coffee shop, fitness app, "Fleet overview", Shipments and On time); no numbers added
* New dev dependencies, listed in CLAUDE.md: `@fontsource/cormorant-garamond`, `@fontsource/figtree`, `@fontsource/rubik`, `@fontsource/barlow-semi-condensed`

## M2 · Demo screens: Projects, Review, Project history, Compare (2026-10-17)

Built

* `lib/compare.ts` (docs/07): normalised boxes, IoU, token Jaccard title similarity, greedy best pair matching, fixed / still open / new, and "was … now …" values for fixed measured issues (same kind, IoU ≥ 0.25 or exact label, otherwise "no longer found"). Unit tests for every docs/07 fixture: identical versions, everything fixed, moved element, same principle in two places, null regions, plus value lookups
* `lib/principles.ts` (docs/05 catalogue, "My rule: <text>" for own rules), `lib/format.ts` (dates, values, trend line, summary line, "Checked against …"), `lib/regions.ts` (percent positions, badge offsets), each unit tested
* Projects (1) with thumbnails, severity counts, trend line, "Add a project" and Recent reviews (latest 10); First use (7) when there are no projects, with Reset demo in demo mode
* Project history (2): versions newest first with Latest, context, counts and Open review; Issues per version bars (decorative, numbers in text); Where I disagreed; Compare and Review a new version; Delete project icon button with the screen 15 dialog (Keep project focused first, real counts, toast after deleting)
* Review (4): filters with counts (`aria-pressed`), regions in percentages, badges as buttons that open and focus their card, cards as disclosure buttons with only one open, push back with required reason, Undo, announcements through the Announcer; `?issue=` opens a card (used by Compare's "Open in v2 review")
* No issues found (12) with what the review was checked against, Compare with, Back to project and "Fixed since v<n>" computed with `compareReviews`
* Compare (5): From and To selects (default the two newest finished versions), tiles, side by side screenshots, the three lists, "I disagreed in v<n>: <reason>", By severity table
* Playwright in demo mode with axe on every state: projects, first use, project history, delete dialog, review (keyboard only: badges, cards, filters, push back, error, cancel, save, reload, undo), prepared pushback, shared badge corners, compare, no issues, and 375 px reflow for every new screen

Decisions

* `VersionSummary` gained `context`, `reviewedAt` and `counts`; `ProjectSummary` gained `previousVersionName`. Screens compose Recent reviews and Where I disagreed from the existing `DataClient` methods, so the interface did not change
* Pushed back badges and card numbers use the muted text colour (`#4A5260`) instead of `#8A93A3`: white numbers on `#8A93A3` are 3.2 : 1, below 4.5 : 1. The region box itself stays `#8A93A3`
* Region badges are 44 × 44 px buttons around a 24 px dot. Badges of regions that share a top left corner (two checks on one text line) are shifted sideways so both stay visible and reachable
* Filter buttons use the input border colour (3.1 : 1) instead of the design's `#C5CBD4`
* Thumbnails show the real screenshot (top of the image), not the abstract shapes in the designs
* The push back form has one field, so its error shows under the field and focus stays in it, instead of an error summary
* "Compare with v<n>" on a review points to the previous finished version, or the next one for the first version
* An evaluated fixed item shows "Evaluated · severity · principle"; the design's "labels now above each field" is not data the app has, so it is not shown
* The full Reviewing, Review failed and Evaluation unreadable screens come in M3 and M5; for now a running review polls and shows one line, and partial reviews show the measured issues with the banner text. The "Evaluation is off" note needs the live mode signal from M5
* The Delete project dialog from screen 15 was built here because the button is part of screen 2; M3 only needs to check it
* `<img>` is used for screenshots (with a lint exception) because regions are placed on the exact image and live screenshots will come from local files
